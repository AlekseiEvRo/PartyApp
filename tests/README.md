# Тесты PartyApp

Два проекта xUnit:

| Проект | Что проверяет | Тестов |
|---|---|---|
| `PartyApp.UnitTests` | Сервисы, обработчики ивентов, middleware, EF-конфигурации — без HTTP | 429 |
| `PartyApp.IntegrationTests` | API через `WebApplicationFactory`, реальные миграции, SignalR | 286 |

Общий запуск из корня репозитория:

```powershell
dotnet test PartyApp.sln
```

Запуск только одного проекта / класса:

```powershell
dotnet test tests\PartyApp.UnitTests
dotnet test tests\PartyApp.IntegrationTests --filter "FullyQualifiedName~QuizHandlerTests"
```

Покрытие (coverlet уже подключён; отчёт появится в `TestResults/`):

```powershell
dotnet test PartyApp.sln --collect:"XPlat Code Coverage"
```

## PartyApp.UnitTests

Тестирует боевые классы напрямую: реальный DI-контейнер, реальная SQLite
in-memory и записывающие фейки вместо инфраструктуры.

### Инфраструктура (`Testing/`)

| Класс | Назначение |
|---|---|
| `SqliteTestHost` | DI-контейнер + SQLite `Data Source=:memory:`, `EnsureCreated`, scopes как в проде |
| `FakePushNotificationService` | Записывает push-вызовы (`Calls`) вместо отправки |
| `RecordingHubContext` | Записывает рассылки SignalR: адресат (`user:{id}`, `all`), метод, payload |
| `TestData` | Фабрики сущностей (`User`, `EventDefinition`, `EventSession`, `QrToken`) |
| `TestConfiguration` | In-memory `IConfiguration` |
| `TempDictionaryFile` | Временный словарь для `WordRushHandler` |

### Что покрыто

- **Auth**: `TokenService` (claims, issuer/audience, срок жизни, подпись ключом,
  `stamp`), `AuthService` (регистрация, валидация, дубликаты, приветственный
  бонус, логин, блокировка), `JwtSigningKeyStore` (конфиг → файл → генерация,
  короткий ключ, битый файл), `PasswordGenerator`.
- **События**: `EventService` (старт/финиш/сабмит/доступные ивенты/данные,
  `EndsAt` по длительности ивента, автозакрытие просроченных сессий),
  `EventHandlerFactory` (регистрация, дубликаты, case-insensitive),
  `QrTokenService` (лимиты, формат кодов, уникальность, статистика
  по игрокам и имя активировавшего), `RussianDictionaryService` (Ё→Е,
  регистр, отсутствующий файл).
- **Обработчики ивентов**: `quiz`, `word_rush`, `promo_code`, `qr_scan`,
  `quick_checkin`, `reaction` (тайминг от серверного времени, таблица
  результатов после окна), `dare`
  (ровно один фант на игрока, без баллов до подтверждения), `bingo`
  (два этапа: выбор фиксированного числа клеток, снятие выбора, блокировка
  приёма и возврат, подтверждение клеток, линии по подтверждённым),
  `emoji_song` (нормализация ответа), `predictions`
  (одно предсказание, раскрытие после финиша), `raffle`
  (билеты со случайными уникальными номерами, первый бесплатный,
  доплата за следующие, один розыгрыш на сессию), `spyfall`
  (выдача ролей и слов, тайное голосование со сменой голоса, итог по
  большинству, одна попытка шпиона, закрытие без результата,
  нормализация ответа и разбор конфига) — все ветки ошибок
  и успеха, повторные попытки, дефолты конфигов и валидность
  `DefaultConfigJson` (заготовки для админки).
- **Кошелёк**: `PointsAwardService` — создание/обновление кошелька, транзакции,
  `BalanceUpdated`, push с троттлингом; `TrySpendAsync` — атомарное списание
  без гонок.
- **Аукцион**: `AuctionService` — удержание ставки, доплата при повышении,
  запрет понижения/после дедлайна/без баллов, закрытие с возвратом проигравшим,
  отмена с полным возвратом, автозакрытие просроченных лотов.
- **Toast/SpyGame**: кулдауны и тайминги через `FakeTimeProvider`,
  роли рассказчик/угадчик, обвинения, победы, ничья.
- **Push**: VAPID из конфига/файла, автогенерация и переиспользование ключей.
- **Файлы**: `LocalFileStorage` — сохранение/чтение/удаление, уникальные пути,
  валидация расширений и папок (`avatars/`), защита от path traversal.
  `BackupService` — zip с базой (проверяется извлечением и чтением), ключами
  и uploads, ротация архивов, список копий.
- **Достижения**: `AchievementService` — первый ответ, пять одобренных фото,
  пять QR, три подтверждённых фанта, сотня заработанных баллов (приветственный
  бонус не считается), победитель квиза, пять лайков на фото, линия бинго;
  повторная выдача не начисляет баллы, есть `AchievementUnlocked` и push.
- **Голосование**: `PollService` — создание закрывает предыдущее голосование,
  один голос на игрока с возможностью передумать, запрет голосовать после
  закрытия и за несуществующий вариант, закрытие, запуск победителя через
  `IEventService`, «последнее голосование» с моим выбором.
- **Инфраструктура**: `ExceptionHandlingMiddleware` (400/500), EF-конфигурации
  (уникальные индексы, каскады, конвертер дат в UTC), `SubClaimUserIdProvider`.

## PartyApp.IntegrationTests

`PartyAppFactory` поднимает настоящее приложение: временная SQLite-БД в Temp,
реальные миграции и сид из `Program.cs`, тестовый JWT, фейковый push.
`PartyAppApi` — обёртка над `HttpClient` (регистрация, логин, админ,
авторизация, баланс). Параллельность тестов выключена (`AssemblyInfo.cs`).

### Что покрыто

- **Auth/Wallet/Admin**: регистрация/логин/`me`, приветственный бонус,
  403 для игроков, лидерборд, ручные начисления и списания, история транзакций
  кошелька с пагинацией.
- **Управление игроками/аудит**: переименование, смена роли, бан/разбан, кик
  и сброс пароля (только админ), защита от действий над собой, старые токены
  после смены роли/бана/кика получают 401, заблокированный не может войти,
  действия попадают в `GET /api/admin/audit` с именами админа и цели.
- **Супер-админ**: доступ к админке, роль супер-админа не меняет никто,
  назначает только супер-админ, бан/кик/сброс пароля супер-админа — только
  другому супер-админу; рядовой админ по-прежнему управляет игроками
  и админами.
- **Бэкапы**: `GET /api/admin/backup` отдаёт zip с `party.db`, список копий
  доступен через `GET /api/admin/backups`; автобэкап на старте создаёт файл;
  игрокам — 403.
- **Health**: `/health` отдаёт `status=ok` и `database=ok`.
- **Профиль**: загрузка аватара (проверка сигнатуры, замена старого файла,
  лимит размера), отдача и удаление, статус-эмодзи с очисткой, версия профиля
  в админском лидерборде, 401 без токена.
- **Достижения**: каталог без полученных, «Первый шаг» за первую отправку
  (+5 к балансу), победитель квиза получает достижение только он, 401 без токена.
- **Голосование**: полный цикл «создать → проголосовать → передумать →
  закрыть → запустить победителя» (ивент реально стартует), валидация вопроса
  и вариантов, конфликты после закрытия и без голосов, 403 для игрока.
- **Rate limiting**: при превышении лимита `/api/auth` возвращает **429**
  с JSON-ошибкой; при `RateLimiting:Enabled=false` лимиты не действуют.
- **Events**: полный E2E-сценарий «админ стартует квиз → игрок отвечает →
  баланс растёт → повтор отклоняется → админ завершает», `available`,
  `data`, определения и CRUD (`POST/PUT/DELETE /api/events/definitions`,
  `GET /types`), конфликты старта/финиша, `durationMinutes` и `endsAt`
  при старте и в списке доступных ивентов.
- **Магазин/Аукцион**: покупка со списанием и остатком (`out-of-stock` и
  нехватка баллов — 409), выдача призов, удаление товара с покупками — 409;
  лот-черновик скрыт и не принимает ставки до «Начать», после старта виден
  лидер и сумма (открытый аукцион), победа максимальной ставки, возврат
  проигравшим, отмена лота, права админа. Живые события `ShopUpdated`,
  `PurchaseUpdated`, `LotStarted`, `BidPlaced`, `LotFinished` приходят
  игрокам без перезагрузки; `GET /api/shop/lots/winners` отдаёт завершённые
  лоты с победителями.
- **Фанты**: игрок тянет фант (баллы не начисляются), второй фант — 409,
  админ видит очередь и подтверждает, баллы начисляются один раз
  (повторное подтверждение — 409), игроку уходит `DareConfirmed`.
- **Бинго**: отметка клетки баллов не даёт; админ видит счётчик отметок
  и подтверждает событие — баллы получают отметившие, повторное
  подтверждение — 409, у игрока появляется подтверждённая клетка.
  Бонус за линию получают все, кто её собрал, — по разу на игрока.
- **«Шпионы»**: запуск из админского эндпоинта с выбором состава (обычная
  кнопка старта — 409), ивент и данные скрыты от посторонних, конфиг с
  парами слов игрокам не отдаётся; голосование горожан, победа по
  большинству с начислением только верным голосам, попытка шпиона
  (неверная сгорает, вторая — 409), закрытие до конца голосования —
  раскрытие без баллов.
- **Toast/QR/Push/Notifications**: реальный кулдаун тостов, одноразовые
  QR-коды (некорректные count/points — 400), статистика `/api/qr/stats`
  и имя активировавшего в списке, защита от SSRF в подписке
  на push, рассылка сообщений ведущего.
- **Фото/Отзывы**: загрузка с проверкой сигнатуры и лимита размера, лента,
  лайки-переключатели, модерация (скрыто до одобрения), права на удаление;
  стенка отзывов с премодерацией и видимостью только одобренного. Удаление
  и отзыв одобрения рассылаются по SignalR (`PhotoRemoved`/`WishRemoved`),
  чтобы элементы исчезали у всех без перезагрузки. О новом контенте на
  модерации админам приходят `ModerationPending` (только в группу `admins`)
  и push с тегами `moderation-photo`/`moderation-wish`.
- **Экран**: `ScreenService` — режимы (включая `qr` и `spy`), версии
  состояния и конфетти; API
  `/api/screen/*` с валидацией (режим, sessionId, сообщение, реакции,
  настройки ротации) и правами: режимы и таймауты меняет админ, конфетти
  и стикеры/подписи доступны игрокам. Рассылки `ScreenUpdated`,
  `ScreenConfetti`, `ScreenReaction` и `ScreenSettingsUpdated`; «живые»
  данные ивента (`live` в `GET /data`, `EventLiveUpdated`) — например,
  кто говорит тост.
- **SignalR**: настоящий `HubConnection` через `TestServer` — отказ без токена,
  `BalanceUpdated`, `EventStarted`, `ReceiveBroadcast`, `SpyGameRoleAssigned`,
  `PhotoRemoved`, `WishRemoved`, `ModerationPending` (админам и никому другому),
  `ScreenUpdated`, `ScreenConfetti`, `SessionRevoked` (кикнутому игроку),
  `ProfileUpdated`, `AchievementUnlocked` и `PollUpdated`.

## Известные ограничения, зафиксированные тестами

Это не баги тестов, а текущее поведение приложения:

- В `PlayerSubmissions` сохраняются и отклонённые попытки (например, повторный
  ответ на вопрос квиза) — со `Score = 0`.
- `TryGetProperty` в обработчиках чувствителен к регистру ключей payload,
  поэтому клиент обязан слать camelCase (`questionIndex`, `answerIndex`, `word`).
- Смена роли, блокировка, кик и сброс пароля инвалидируют все выданные токены
  игрока (`SecurityStamp`), поэтому после них нужен повторный вход. Активное
  SignalR-соединение получает `SessionRevoked` и разлогинивается на клиенте.
